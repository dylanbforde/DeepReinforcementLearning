## 2024-03-24 - PyTorch In-Place Interpolation Optimization
**Learning:** Explicit arithmetic (`TAU * policy + (1 - TAU) * target`) in PyTorch training loops (specifically in RL soft target updates) forces the allocation of multiple intermediate tensors per operation. This creates a severe memory allocation overhead and slows down the loop when it could be entirely performed in C++/CUDA. Using `.lerp_()` on the target tensor parameters instead executes the equivalent mathematical operation mathematically in-place, bypassing the redundant overhead completely.
**Action:** Always prefer PyTorch's optimized in-place mathematical operations (like `lerp_`, `addcdiv_`, or `addcmul_`) within tight loops rather than chaining arithmetic primitives, significantly minimizing memory overhead and accelerating network updates.

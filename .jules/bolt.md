## 2024-05-24 - [PyTorch Tensor Creation and Soft Update Optimizations]
**Learning:** In PyTorch, constructing a random tensor on the CPU using `np.random.uniform` and then moving/casting it to the GPU via `torch.tensor` is ~3x slower than instantiating the memory directly on the device with `torch.empty(...).uniform_()`. Additionally, when performing target network soft updates via a convex combination of two tensors, doing so via explicit intermediate math (`t.copy_(TAU * p + (1.0 - TAU) * t)`) allocates intermediate tensors and is over 20x slower than using the in-place `.lerp_()` operator.
**Action:** Always prefer initializing random tensors via PyTorch's native methods and device mappings rather than doing NumPy-to-PyTorch conversions, and use in-place linear interpolation `lerp_` for any weighted average tensor updates (like DQN soft target updates).
